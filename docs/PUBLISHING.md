# Publishing Sand to GPU

The source repository and the hosted course are separate releases. Making GitHub public does not deploy the website or upload the narration. This preparation does neither.

## Before changing repository visibility

1. Review [licensing](LICENSING.md) and [third-party notices](../THIRD_PARTY_NOTICES.md), including the scope of educational content and generated recordings.
2. Read the [public-readiness audit](PUBLIC_READINESS_AUDIT.md). Current-file cleanup does not remove earlier versions from Git history. The retained history includes original workstation/session references, author identity, email, and signed-commit metadata. Decide whether that history is acceptable before changing visibility; any history rewrite is a separate operation.
3. Confirm the build checks pass on the intended commit. See [build validation](BUILD_VALIDATION.md) for the checks actually run during preparation, and [contributor instructions](../CONTRIBUTING.md) for reproducing them.
4. Enable GitHub private vulnerability reporting and the desired branch protections in repository settings. The repository templates and CI do not enable those settings themselves.
5. Change visibility only when the owner is ready. No workflow in this project changes visibility or publishes a website.

## A website without recorded narration

Run `npm ci` and `npm run build`. The `site/` directory contains the static application: HTML, CSS, JavaScript, generated lessons, and interactive figures. Serve it with a static HTTP host; opening `index.html` directly as a local file is not the supported setup.

For a public static-only edition, add the following line inside the exported copy's `<head>` in `index.html`:

```html
<meta name="narration-mode" content="static">
```

This marks playback as recorded-audio only, so missing recordings do not trigger calls to a local generation API. Without the narration assets, reading, labs, quizzes, search, and Markdown export still work; listening is unavailable. Keep the marker out of the development source if you want to use local speech generation there.

Copy `LICENSE`, `LICENSE-CONTENT`, `docs/LICENSING.md`, and `THIRD_PARTY_NOTICES.md` alongside the published assets, preserving their relative paths. The reader uses hash routes such as `#/s/01`, so chapter paths do not require server rewrite rules. If deploying below a URL subdirectory, test navigation, Markdown download, and any narration at that exact base path.

The site loads Google Fonts over the network, with local fallback fonts. It does not embed an AI provider: copying a chapter makes text available for the reader to paste elsewhere. Browser-local reading progress is not an account or a server-side profile.

## A website with recorded narration

Audio is generated by the maintainer once, then served as static MP3 files with passage manifests and word timestamps. Visitors do not download or run Kokoro. The Git checkout excludes the model, Python runtime, cached WAVs, and recorded MP3s.

To regenerate the recording edition, install `uv` and FFmpeg, and use a browser supported by the QA harness. The optional local runtime uses Python 3.12.3 and downloads the pinned Kokoro model. See the setup limits in [build validation](BUILD_VALIDATION.md). A full course render requires substantial time and disk space.

In one terminal, build and serve the same source you intend to render:

```sh
npm ci
npm run build
npm start
```

In another terminal, from the same repository:

```sh
npm run narration:setup
npm run narration:inventory
npm run narration:prerender -- --workers 1
npm run narration:export -- --ffmpeg /absolute/path/to/ffmpeg
```

Replace the FFmpeg argument with the actual executable path (`ffmpeg.exe` on Windows). The inventory and final export check the server at `http://127.0.0.1:8790`; set `QA_BASE_URL` if serving on another port. Keep the source server running through finalization.

By default, generated files live under the current user's `.cache/sand-to-gpu/` directory. `NARRATION_HOME` changes that base directory. The finalized website is in `static-export/` beneath it. Keep the default inventory, progress, and export locations together unless deliberately configuring all three.

Rendering is resumable. Run the same commands again after interruption; cached passages are reused. The export finalizer verifies coverage, converts recordings to MP3, updates manifests, and adds the static-only marker. Publish only after both rendering and finalization report completion. Copy the **whole finalized directory**, including `narration/index.json`, lesson manifests, and `narration/audio/`, together with project license and notice files.

For ChatGPT Sites static publishing, keep the generated recordings in small hash-prefix subdirectories under `narration/audio/` (for example, `audio/fd/<key>.mp3`) and update each manifest's `audioUrl` to match. This avoids the host's per-directory asset limit while preserving the reader's relative URL handling. Ogg/Opus is a useful speech-quality option when the Sites bundle cap makes low-bitrate MP3 sound muffled; set the index format metadata and verify `audio/ogg` playback in the target browsers.

The current high-quality public edition stores its 64 kbps MP3 recordings in the public GitHub Releases `narration-64k-0` through `narration-64k-f`. The Sites bundle carries the manifests and points each passage at the matching release asset, keeping the multi-gigabyte recordings out of the Sites archive.

The [historical recording report](../PRERENDER_2026-09-13.md) records the existing 32-lesson edition and archive checksum. That local artifact is not a public download. A future release may attach a verified archive separately from Git source. Do not add gigabytes of recordings to ordinary Git history.

## Release checks

- Visit both tracks at the deployed URL; test search, chapter navigation, a lab, a quiz, and Markdown copy/download.
- For the recording edition, start playback, seek to another paragraph, change speed, and check word highlighting. Confirm there are no requests to `/api/narration/`.
- Check a phone-width layout and both themes. Automated checks do not replace reading the diagrams at their displayed size.
- Record the source commit, archive checksum, asset coverage, and any known limitations. Keep the current README links pointed at a real release or hosted URL only after those exist.

The local Node server is a development tool with optional inference endpoints. Public hosting should serve the static edition, without the model runtime or generation API.
